# 对象存储清单与分区现存文件对账

        面向一线复核人员的单服务数据工作台。样例数据随仓库提供，结论保留行号、原因码和原值。

        ## 业务模块

        - M1 清单采信：`/api/manifests/import`
- M2 路径契约：`/api/paths/normalize`
- M3 对象核验：`/api/objects/verify`
- M4 分区判定：`/api/partitions`
- M5 差异对账：`/api/reconcile`
- M6 批次导出：`/api/export/differences.csv`

        ## 核心规则

        路径规范化后按 key、size 与摘要逐项比对，目录标记、空分区和缺失对象不得混为一类。

        批次绑定三件东西：清单指纹、计算规则版本、路径规则版本。对象元数据发布成不可变快照，
        同一清单可以对新快照另开对账，旧批次复核只读当时快照里的 size 与摘要；缺少快照的批次
        拒绝重算。采集可断点续跑，写入失败不发布半批，重试不重复登记。

        ## 启动

        ```bash
        docker compose up --build
        ```

        浏览器访问 `http://localhost:18211`。运行测试：

        ```bash
        docker compose exec -T app pytest -q
        ```

        ## 样例流程

        1. 在清单采信页导入样例清单，得到 `batch_id`（清单 + 规则版本 + 路径规则版本）。
        2. 在对象核验页选该批次采集样例对象，得到 `snapshot_id`；分段采集时按返回的
           `collection_id` 续跑即可，已采对象不重读。
        3. 在差异对账页选择批次与快照（当前或历史）复核，缺失分为目录标记、空分区、缺失文件。
        4. 在批次导出页按批次导出证据 CSV，每行带 `batch_id` 与 `snapshot_id`。

        同一清单再采一次得到新快照即可对比新差异，历史对账记录不变。

        ## 已知不覆盖

        不处理加密文件与需要外部密钥的对象；不连接真实生产存储。
